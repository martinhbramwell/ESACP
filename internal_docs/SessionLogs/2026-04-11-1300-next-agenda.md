# Agenda — Next Session

**Objective:** Redesign the VM provisioning/differentiation pipeline as an atomic, IoC-based task system.

---

## Context

The current pipeline is a 300+ line bash monolith (`differentiate.sh`) called by two separate Python code paths (`_run_provision_erpnext` and `_run_refresh`) that overlap but diverge on prerequisites. This session exposed four concrete gaps (WireGuard, deploy keys, BKP, TLS cert) where refresh silently omits work that provision does. The root cause is architectural: no task atomicity, no state awareness, no shared post-VM-creation path.

See #154 for full analysis.

## Design Principles (agreed this session)

1. **Every task is atomic and self-contained** — receives its dependencies via constructor injection, never reaches into globals
2. **Explicit precondition checks, not "known good" lists** — each task inspects actual system state (file exists? service running? cert valid?) rather than trusting a central record
3. **IoC / Dependency Injection** — tasks receive a frozen Config with SSH connection, paths, secrets; the orchestrator constructs it
4. **One code path** — provision = create VM + ensure_and_differentiate(); refresh = ensure_and_differentiate() directly
5. **Environment-aware stages** — each environment (local KVM, CloudStack, VPS) declares which tasks apply and what parameters they need
6. **State tracking via precondition checks** — re-runs skip already-completed work because each task checks its own postconditions before acting

## Priority

### 1. Define the task interface

```python
@dataclass(frozen=True)
class TaskResult:
    success: bool
    changed: bool  # did the task modify anything?
    message: str

def task(config: Config) -> TaskResult:
    """Check preconditions, act if needed, report."""
```

### 2. Extract the first batch of tasks from differentiate.sh

Start with the prerequisite tasks that caused today's failures:
- `ensure_connectivity` — try WG IP, fall back to ProxyJump
- `ensure_deploy_keys` — check VM, SCP if missing
- `ensure_bkp` — check VM, rsync if missing
- `ensure_tls_cert` — check VM, distribute from saconsole if missing

### 3. Build the pipeline runner

A simple loop over a task list. Constructs Config from hosts_map.yml + SOPS secrets. Calls each task. Logs results. Stops on failure (with clear error).

### 4. Unify provision and refresh

`_run_provision_erpnext` and `_run_refresh` both call the pipeline runner. Provision prepends VM creation tasks.
