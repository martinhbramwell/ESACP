### Sub-step 1 — Mandatory grep gate

Per the Stage 3 block:

- For each session N in window (S11→S62), identify the primary
  issue/topic T (from session's "Session scope" / "Agendaed" /
  "Actual scope" lines).
- Run `grep -rln <T's-key-terms> memory/` — the *relevant* memory set.
- Read session N's "Sub-step 1 / Work done" — the *consulted* memory
  set.
- Set-difference (relevant minus consulted) = potential miss.

Capture the gate-applied corpus into the Stage 3 report subsection.

### Sub-step 2 — Per-session triage (S11→S62, ~52 rows)

Full-pass shallow triage. Per session, one row in the triage table:

| Session | Date | Primary issue/topic | Key memory terms | Grep evidence | Verdict |
|---|---|---|---|---|---|

Verdict values: **Y** (grep evidence in Sub-step 1 / Work done), **N**
(no grep evidence found; itemise in no's table), **n/a** (session was
pure ops/no memory-relevant topic, e.g. sync-check fix, hosts_map
correction with no memory implications).

### Sub-step 3 — No's table + corrective measures

- Already-shipped (e.g., S56 → `feedback_grep_memory_before_issue_body.md`)
