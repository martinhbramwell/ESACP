## Objective for Session 111 — PINNED

**#658 — `create_snapshot` masks failures + transient final-snapshot retry.** The durable plan is on
the #658 issue (read it + the S110 correction comment first via `gh issue view 658 --comments`). Summary:

- **Masking (the dangerous bug)**: `tools/pipeline/orchestration/snapshot_ops.py:create_snapshot`
  returns `False` on failure, but `macro/provision.py` + `macro/provision_generic.py` ignore the return
  and report "complete" → a snapshot-less VM looks like a successful build (breaks idempotency gate,
  rollback, self-repair; violates no-masking).
- **No retry**: the final post-provision snapshot can fail transiently right after heavy bench/site
  I/O ("Extra element disks in interleave" on toshiba's libvirt 6.0.0); it self-resolves in seconds.
- **Fix**: `create_snapshot` retries N times with short backoff; the final-snapshot step in both macros
  treats an exhausted-retry `False` as a **provision failure** (raise), not a warning. Colocated test.
- **Acceptance**: a 24.04-template provision gets its Baseline snapshot (with retry), and a forced
  snapshot failure makes the provision fail loudly (no silent success). Per `feedback_acceptance_test_required`.
