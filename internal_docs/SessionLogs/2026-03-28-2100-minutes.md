### Bug #57 — nginx cannot serve static assets: `/home/adm` lacks `o+x` ✅ (commit 9ec1020)

**Symptom:** All CSS and JS assets returned HTTP 503.

**Root cause:** `/home/adm` was created with `drwxr-x---` (group=`users`). nginx runs as
`www-data` which is not in group `users` → EACCES on every `stat()` call into the bench's
`sites/assets/` directory.

**Fix:** `sudo chmod o+x /home/$ERP_USER` added to differentiate.sh section A3 (after
supervisor setup, before D).

---

### Bug #58 — admin password overwritten by `bench restore` ✅ (commit 9ec1020)

**Symptom:** Login failed with "Invalid Login" after pipeline completed.

**Root cause:** `bench restore` replaces the entire MariaDB database including the `__Auth`
table. The `--admin-password sasa` set during `bench new-site` was overwritten by the
production DB's password hash.

**Fix:** New section H3 in differentiate.sh after bench restart:
`bench --site $SITE_URL set-admin-password $ERP_USER_PWD`

---

### Bug #59 — Company logo (and all `/files/`) returning 404 ✅ (commit b11058a)

**Symptom:** `LogichemLogo.png` returning 404 despite file existing on disk at
`sites/dev01.iridium.blue/public/files/LogichemLogo.png`.

**Root cause:** The custom nginx config in section J used bare `try_files $uri @webserver`.
With `root /home/adm/frappe-bench-D1IRBL/sites`, nginx looked for
`sites/files/LogichemLogo.png` — missing the site-name/public prefix.
Bench-generated config uses `try_files /dev01.iridium.blue/public$uri @webserver`.

**Fix:** Updated nginx template in tools/api.py:
- `location /files/`: `try_files /{site_url}/public$uri @webserver`
- `location /`: same fix
- `@webserver`: added `X-Frappe-Site-Name` and `X-Use-X-Accel-Redirect True` headers
  (matches what `bench setup nginx` generates)
