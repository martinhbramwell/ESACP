### Hypotheses ranked (from #296 issue body)

1. Chrome aborts the request internally (HTTP/2 connection reaping, navigation detach) even though spec code does not.
2. `waitForFrappeIdle(page)` on line 176 leaves the page in a state where the click lands but the response promise is never reified into Playwright's listener.
3. Response arrives but matches a different listener scope or is drained by prior `waitForFrappeIdle` polling.
4. The 180s timeout is hit because the click did not actually deliver the POST — phantom click — and the 35s backend timing is from a prior duplicate request.

### Likely fix shape (educated guess — verify before committing)

Wrap the Complete Setup click + response wait with the same DOM-mutation pattern that #267 used for the modal-during-click race:

```js
await waitForFrappeIdle(page);
await page.evaluate(() => {
  // Force-clear any residual freeze backdrop before click
  document.querySelectorAll('#freeze.modal-backdrop').forEach(el => el.remove());
});
const completeButton = page.getByRole('button', { name: 'Complete Setup' });
await completeButton.waitFor({ state: 'visible' });
const [completeResp] = await Promise.all([
  page.waitForResponse(
    r => /setup_complete/.test(r.url()) && r.request().method() === 'POST',
    { timeout: 300_000 },  // longer ceiling — handler can stretch under pipeline load
  ),
  completeButton.click({ force: true }),
]);
```

Or — alternative fix shape — switch from `page.waitForResponse` to `page.route()` interceptor that captures the POST then resolves on the response body, dodging the response-listener ordering question entirely.
