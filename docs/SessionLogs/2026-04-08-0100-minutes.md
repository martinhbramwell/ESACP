## What was done

### 1. Root cause analysis of #122
- `before_install()` in ce_sri `install.py` has two phases: file patches (Procfile, supervisor.conf, nginx vhost) and API work (confirm connection, Custom Scripts, Node.js config)
- Both ran in a single function — file patches sabotaged the running service, then the API calls failed
- H2b polled gunicorn with WARN-and-continue — never actually gated downstream steps

### 2. Split before_install (ce_sri commit `2763c65`)
- `before_install()` now does file patches only (no gunicorn needed)
- New `after_restart()` does API work with 120s gunicorn poll loop
- `after_restart()` re-initializes its own state (collectEnvironmentValues, loadInstallationParameters, GLOBALS.read) since `bench execute` runs a fresh Python process

### 3. Pipeline changes (ESACP — merged PR #128 + direct commits to main)
- **H2a** (new): adds `127.0.0.1 $SITE_URL` to `/etc/hosts` — gunicorn binds to 127.0.0.1 only, hostname resolves to WG IP externally. Portable across KVM and VPS.
- **H2b**: converted from WARN-and-continue to hard `exit 1`. Timeout increased to 120s. Uses real hostname URL (works because H2a makes it resolve locally).
- **H4d**: now calls `before_install` (file patches only)
- **H4g** (new): after H4f restart, calls `after_restart` (API work with internal poll)
- dev02-differentiate.sh artifact updated with all above changes

### 4. Discoveries during acceptance testing

#### Gunicorn binds to 127.0.0.1 only
- `ss -tlnp` shows gunicorn on `127.0.0.1:8000`, not `0.0.0.0:8000` (Frappe default)
- WireGuard IP (10.10.0.12) is unreachable on port 8000 from the VM itself
- Fix: H2a `/etc/hosts` entry — resolved the ConnectionError

#### H2b needed Host header (pre-/etc/hosts)
- Without `currentsite.txt`, Frappe returns 404 to bare `curl http://127.0.0.1:8000/api/method/ping`
- Needed `Host: dev02.iridium.blue` header — but this was superseded by the `/etc/hosts` approach

#### 403 on API key — PRE-EXISTING BUG exposed by fixing the connection
- `collectEnvironmentValues()` at line 203 reads only the FIRST line of `apikey.sh` (`API_KEY="..."`)
- This gives just the api_key, not the full `api_key:api_secret` token
- Authorization header becomes `token 56435adde957d7f` instead of `token 56435adde957d7f:secret`
- `loadInstallationParameters()` skips the parms file value because config_file_data is already set (not None)
- The third line of `apikey.sh` has `KEYS="key:secret"` — that's what the code needs
- This bug was ALWAYS present but never triggered because ConnectionError prevented reaching the API call
