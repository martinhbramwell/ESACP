## Item 1: New issue — hardcoded "saconsole" VM name

During the rebuild acceptance test, we identified that the VM name "saconsole" is hardcoded
in ~320+ occurrences across 40+ files (platforms/kvm/, ansible/, tools/, docker/).

Issue #9 fixed IPs, usernames, and hypervisor identity via `config.sh` + `parse_hosts_map.py`,
but the VM name itself was never parameterised.

1. Open issue with full inventory of affected areas
2. Propose approach: add `ESACP_SACONSOLE_HOSTNAME` to `parse_hosts_map.py` output,
   then find-and-replace in scripts (keeping cloud-init `hostname` and Ansible inventory
   derived from `hosts_map.yml`)
3. This is a large refactor — plan only, no implementation in this session

## Item 2: #37 — jobs run as uvicorn tasks

The provisioning job for dev02 took ~28 minutes. If uvicorn had restarted mid-job,
all progress would be lost. This is a real operational risk now that the pipeline is proven.

Options to investigate:
- Background job runner (Celery, RQ, or simple subprocess with PID file)
- Job state persistence to disk (resume on restart)
- At minimum: write job log to a file so it survives uvicorn restart
