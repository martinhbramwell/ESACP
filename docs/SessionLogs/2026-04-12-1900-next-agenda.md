# Agenda — Next Session

**Objective:** Wire macro/provision.py to call stage orchestrators 1–9 sequentially.

---

## Context

All 9 stages are extracted into `tools/pipeline/stages/stage_N_*/` with orchestrators (`run_stage_N(config, emit)`) and verify gates. The macro scripts (`tools/pipeline/macro/provision.py`, `refresh.py`) exist as skeletons. `api.py` still contains the monolithic `_run_provision_erpnext()` (~400 lines) and `_run_refresh()` which duplicate the stage logic inline.

The `build_config()` function in `stages/common/config.py` constructs the immutable Config from `hosts_map.yml`. The runner in `pipeline/runner.py` is a generic task executor, but the stages use a different pattern (`run_stage_N(config, emit) -> None`, raising RuntimeError on failure) rather than returning TaskResult.

## Scope

### 1. Wire macro/provision.py

- Import all 9 `run_stage_N` functions
- Construct Config via `build_config(hostname, host_cfg, project_root)`
- Call stages 1–9 sequentially, catching RuntimeError per stage
- Emit progress to the job log (same `emit` callback as api.py uses)

### 2. Wire macro/refresh.py

- Same as provision but starts at Stage 3 (skips VM creation + network)
- Uses `use_wg=True` in `build_config()` (VM already exists, WG is up)

### 3. Replace api.py inline logic

- `_run_provision_erpnext()` → call `macro.provision.run()`
- `_run_refresh()` → call `macro.refresh.run()`
- Keep the HTTP endpoint handlers, job management, and emit wiring

### 4. Test on dev03

- Provision: can't test end-to-end without destroying dev03 — test by verifying all stages skip (idempotency gates)
- Refresh: run full refresh via API, confirm all stages pass verify after

## Design considerations

- **Error handling**: each `run_stage_N` raises RuntimeError. Macro should catch, log, and re-raise so api.py can set job status to failed.
- **Stage 1/2 differences**: provision only. Refresh starts at 3. The macro scripts encode this.
- **Timeout**: api.py currently has per-stage SSH timeouts. The macro script doesn't need additional timeouts — each stage handles its own.
- **Config.target_ip**: provision uses virbr0 (VM just created, no WG yet). Refresh uses WG. The `use_wg` param in `build_config()` handles this.
- **Stage 3 idempotency**: Stage 3 verify checks `/tmp/` artifacts which are consumed. On refresh, these need to be re-deployed. The stage orchestrator should handle this (re-SCP if verify fails).

## Constraints

- One macro at a time — get provision.py working first, then refresh.py
- Keep api.py functional at every commit
- Test idempotency (all stages should skip on a fully-configured VM)
