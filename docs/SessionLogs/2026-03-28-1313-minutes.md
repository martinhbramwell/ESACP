## New Business

### Cloudflare MCP OAuth — Permanent Fix ✅

**Root cause (fully confirmed):** Two independent structural failures:

1. **Token expiry** — `access_token` expires after 1 hour. `mcp-remote` in stdio mode is
   launched fresh by Claude Code on every start. With an expired token it gets a 401, tries
   to trigger browser OAuth — but Claude Code owns stdio, so the URL is never shown. Silent
   failure. Cloudflare tools don't appear.

2. **Version mismatch** — `npm install -g mcp-remote` creates a new token cache dir
   (`~/.mcp-auth/mcp-remote-{NEW}/`). Old tokens sit in old dir. Same silent failure.

**Fix implemented:**

- **`~/.local/bin/cf-mcp-refresh`** — standalone token refresh script:
  - Reads the configured mcp-remote binary from `~/.claude/settings.json`
  - Determines installed version from package.json
  - Migrates token cache to new version dir if needed (handles upgrades)
  - Refreshes `access_token` via `POST https://mcp.cloudflare.com/token` with refresh_token
  - Writes new tokens back; warns but does not block on failure

- **`ESACP/Cld.sh`** — project launch script:
  - `cd`s to ESACP root
  - Calls `cf-mcp-refresh`
  - Launches `claude --chrome`

**Required habit change:** Run `./Cld.sh` instead of `claude` to start Claude Code on this project.

**This session's Cloudflare tools** remain unavailable — MCP servers were already started
with expired token before the fix was implemented. Will be live from the next `./Cld.sh` launch.

**Note:** `cf-mcp-refresh` lives at `~/.local/bin/` — not yet in the repo. See agenda item.
