## Gotchas and design questions to resolve up front

1. **`cmd_verify_vpn` runs against the hub via SSH** — uses `ssh_run(hub_ip, user, key, "sudo wg show")` and parses the output. Sourced hub identity from `host_identity.HUB_VIRBR0_IP` etc. Confirm the new primitive gets the hub identity the same way (consistent with the existing pipeline pattern) rather than receiving it as a parameter.

2. **Interactive password prompt in `cmd_validate_observability`** — this falls back to `getpass.getpass()` when neither env vars nor SSH returns a password. **Business logic in a pipeline primitive cannot prompt the user interactively** (no `input`, no `getpass` — that breaks the `emit`-only rule and prevents non-TTY callers like the API from using the primitive). Options to resolve:
   - (a) Extract the primitive to take `(grafana_user, grafana_password) -> TaskResult`; the dispatcher (esacp CLI) does the env/SSH/prompt sourcing and passes creds in.
   - (b) Extract a `source_grafana_creds(emit, *, interactive: bool = False) -> (user, password) | None` query-only primitive — if `interactive=False` and fallback would prompt, return `None` and let the caller decide.
   - **Recommended: (a)**. Keeps credential sourcing a dispatcher-layer concern (it's I/O policy, not business logic) and keeps the validation primitive callable from api.py later if needed.

3. **`_filter_ansible_line` has mutable `state: dict`** — it carries filter state across invocations. Keep the same contract in the extracted module (`filter_line(line, state)` or wrap in a small class). Don't silently change the interface.

4. **`ansible_output.py` location in `stages/common/`** — this directory currently contains `Config`, `Emit`, `TaskResult`, SSH/SCP helpers. Adding an ANSI-strip + ansible-line filter fits the "generic cross-stage helpers" theme. Verify no namespace collision before writing.

## Risks / what could go wrong

- **ANSI filter regressions invisible to unit tests** — `_filter_ansible_line` runs live during provisioning; a subtle behaviour change (e.g. hiding a line class that was previously shown) only surfaces during a real Ansible run. Mitigation: run `./tools/esacp.py validateObservability` end-to-end; compare filtered output.
- **Credential prompt falling through** — if primitive (b) is chosen and `interactive=False` returns None, the dispatcher must handle None rather than crashing. Prefer (a).
- **Over-extraction** — the plan's line ranges are stale; do not blindly match bytes to the plan. Extract logic units, not line ranges.
- **Touching phase-7 territory** — tempting to also thin the argparse parser or dispatch table "while we're here." Don't. 1 issue = 1 branch = 1 session.
